# LMEP 移植设计文档

> **Luminiflux's MTR Expansion Pack**（流光MTR拓展包 / LMEP）
> 目标：把 MTR4 的「可视化铺轨预览」移植到 **MTR3（Minecraft 1.20.1 + Forge）**，作为独立 Addon。
> 本文档记录 v1.0 的设计依据。所有关于 MTR3 内部行为的结论，均来自对
> `MTR-forge-1.20.1-3.2.2-hotfix-2.jar` 的**反汇编核实**（`javap -p -c`），而非猜测。
> 当前版本：`1.0.0-hotfix-1`。

---

## 0. 目标版本与事实基线

| 项目 | 值 | 来源 |
|---|---|---|
| Minecraft | 1.20.1 | — |
| Forge | 47.2.0（声明 `[47,)`） | — |
| MTR3 Forge 发行版 | `MTR-forge-1.20.1-3.2.2-hotfix-2.jar` | Modrinth（仅 Forge） |
| MTR modId / 版本 | `mtr` / `1.20.1-3.2.2-hotfix-2` | MTR jar 内 `META-INF/mods.toml` |
| MTR 的必需依赖 | `architectury`（modId，版本 `9.2.14` 满足其 `[1.26.37,)`） | 同上 |
| MTR4 蓝本 | 默认分支，包名 `org.mtr.mod`；预览在 `RenderRails` | — |

### 0.1 关键事实：MTR 发行 jar 是 SRG 映射

反汇编证据：`mtr.item.ItemRailModifier` 中 `appendHoverText` 的字节码名字是 **`m_7373_`**，
而 `BlockPos` 等**类名仍是 Mojang 官方名**。

由此推出两条结论，它们决定了整个工程配置：

1. **可以**用 `mappings channel: 'official'` 直接编译。SRG 只重命名 Minecraft 自己的成员，
   **从不改动 MTR 自身的类名与成员名**（`Rail.getLength`、`BlockNode.getAngle`、
   `ClientData.RAILS` … 在 SRG 与 Mojang 下完全一致）。
2. **`fg.deobf()` 无效也无需**。ForgeGradle 对 `files(...)` 依赖会直接报
   *"Cannot deobfuscate dependency … using obfuscated version"*；而对本工程来说，
   保持 jar 原样反而**更正确**——编译期与运行期面对的是同一个 jar。

代价：MTR 自身无法在 ForgeGradle 的 Mojang 开发运行期中运行，因此 **`runClient` 不可用**，
验证必须在真实 Forge 安装上进行。

## 1. 架构决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 注入方式 | **仅 Forge 事件，零 Mixin** | 不与 MTR 自带 mixin（`mtr.mixins.json`）冲突 |
| 状态计算 | `TickEvent.ClientTickEvent`（END） | 主线程，与渲染解耦 |
| 世界渲染 | `RenderLevelStageEvent`（`AFTER_TRANSLUCENT_BLOCKS`） | 半透明混合正确；该事件不提供 buffer，需自建 `MultiBufferSource.immediate` |
| HUD | `RenderGuiEvent.Post` | 官方钩子，可直接用 `GuiGraphics` |
| 轨道几何 | **复用 `mtr.data.Rail`** | 纯数学类；`getPosition(t)` 语义为「沿轨距离」 |
| 幽灵轨道绘制 | **复用 `Rail.render(RenderRail, w, w)`** | 直接得到 MTR 自己的四边形，外观与本体一致 |
| 私有状态 | 反射（缓存 `Field`，失败即降级） | `ItemRailModifier.railType/isOneWay`、`Rail.r1/r2` 无 getter |
| 客户端隔离 | `FMLEnvironment.dist` 守卫 + 独立 `LmepClientSetup` | **1.20.1 的 `@Mod` 只有 `value()`，没有 `dist()` 成员**（已核实） |

## 2. 数据流

```
ClientTickEvent(END)
 └─ TrackPreviewManager.clientTick()
      ├─ 先置 holdingConnector：双手任一手持 ItemRailModifier 且 railType != null（排除拆除器）
      ├─ 再查找同时带 NBT "pos" 锚点的连接器
      ├─ 锚点方块仍是 BlockNode？
      ├─ 准星命中方块且是 BlockNode？（复刻 clickCondition，含 forXxxNode 开关）
      ├─ 复刻 onEndClick：由节点角 + 两点方位角求 facingStart / facingEnd
      ├─ 复刻 onConnect：解析 actualRailType（CABLE_CAR / CABLE_CAR_STATION）
      ├─ new Rail(cursor→anchor) / new Rail(anchor→cursor)
      ├─ valid = 传输方式一致 && 约束满足 && goodRadius && isValid
      ├─ 统计：length3D（采样）/ lengthXZ / ΔXYZ / 坡度 / r1,r2（反射）
      └─ 累计线路长度：锚点沿 ClientData.RAILS 有界 DFS（默认深度 64、访问预算 512，每秒重算）

RenderLevelStageEvent(AFTER_TRANSLUCENT_BLOCKS)
 └─ TrackPreviewRenderer：幽灵轨道丝带 + 节点标记框 + billboard 数值文字

RenderGuiEvent.Post
 └─ TrackPreviewHud：左下角面板（状态 / 长度 / 坡度 / 半径 / 累计 / 提示）
      仅当 holdingConnector 为真（手持轨道连接器）时绘制；未选锚点时只显示一行提示
```

## 3. MTR3 行为还原（逐条对照反汇编结果）

### 3.1 锚点从哪来

`ItemBlockClickingBase.m_6225_`（`useOn`）**在客户端会提前返回**：

```
if (!level.isClientSide) { ...写入/读取 NBT "pos"... }
else return super.useOn(ctx);
```

即锚点由**服务端**写入物品 NBT，客户端通过原版背包同步拿到。
这一点由 MTR 自身佐证：`ItemNodeModifierBase#m_7373_`（tooltip）同样在客户端读
`tag.getLong("pos")` 并显示 `tooltip.mtr.selected_block`。因此 LMEP 读取同一字段是可靠的。

### 3.2 朝向计算（`ItemNodeModifierBase#onEndClick`）

```
angle1 = BlockNode.getAngle(第二个节点)     // 准星所在节点
angle2 = BlockNode.getAngle(锚点)
bearing = toDegrees(atan2(锚点.z - 准星.z, 锚点.x - 准星.x))
facingStart = fromAngle(angle1 + (similarFacing(bearing, angle1) ? 0 : 180))
facingEnd   = fromAngle(angle2 + (similarFacing(bearing, angle2) ? 180 : 0))
```

并且**只有在两点传输方式一致**（`transport_mode` NBT 比对）时才会调用 `onConnect`。
LMEP 复刻该判定，但把不一致显示为「无效：两端传输方式不同」，而不是静默消失。

### 3.3 轨道类型解析（`ItemRailModifier#onConnect`）

```
if (transportMode.continuousMovement) {
    if (两端都是 BlockContinuousMovementNode) {
        if (两端都是 isStation) { ok = true;  actual = railType.hasSavedRail ? railType : CABLE_CAR_STATION; }
        else {
            ok = !railType.hasSavedRail && facingStart.isParallel(facingEnd) && (45° 直线约束);
            actual = CABLE_CAR;
        }
    } else { ok = false; actual = railType; }
} else { ok = true; actual = railType; }
```

> **这是本工程相对朴素实现最重要的修正。**
> `RailType.railSlopeStyle` 参与 `Rail#getPositionY` 的垂度计算，
> 所以用物品自身的 `railType` 代替 `actual`，会让**船与缆车**的
> 三维长度算错、曲线画错。

注意 `TransportMode.BOAT.continuousMovement == true`，因此船轨也走这条分支。

### 3.4 有效性判定

```
valid = ok && rail1.goodRadius() && rail2.goodRadius() && rail1.isValid() && rail2.isValid()
```

失败原因的优先级也与 MTR 一致：
`!ok` → 缆车约束；`!goodRadius` → 半径过小；否则 → 朝向不合法。

`goodRadius()` 的语义（反汇编）：`(isStraight1 || r1 > 1.9999) && (isStraight2 || r2 > 1.9999)`。

### 3.5 轨道几何与外观

* `Rail.getPosition(t)` 内部 `Mth.clamp(t, 0, getLength())`，参数即**沿轨距离**；
  采样它即可得到含竖直起伏的真实三维长度。
* `Rail.render(callback, w1, w2)` 以约 1 格为步长回调
  `(x1,z1, x2,z2, x3,z3, x4,z4, yStart, yEnd)`，即**四角 XZ + 两端 Y**。
  LMEP 直接把这些四边形写入自己的 `VertexConsumer`。
* 轨道半宽与抬升取自 MTR3 `RenderTrains#renderRailStandard` 的调用点：

  | TransportMode | 抬升 | 半宽 |
  |---|---|---|
  | TRAIN | 0.065625 | 1.0 |
  | BOAT | 0.065625 | 0.5 |
  | CABLE_CAR | 0.253125 | 0.25 |
  | AIRPLANE | 0.065625 | 1.0 |

* 贴图使用 MTR 自带的 `mtr:textures/block/rail_preview.png`（16×16，两条竖向轨道条，
  U 横跨轨道、V 沿轨道方向），因此幽灵轨道看起来就是「一条细轨道」。

## 4. 与 MTR4 的对照

| MTR4（蓝本） | LMEP 实现 | 差异 |
|---|---|---|
| `RenderRails.render()` | `TrackPreviewRenderer.onRenderLevel` | Forge 该阶段不提供 `MultiBufferSource`，需 `MultiBufferSource.immediate` |
| `RenderRails.renderRailStats` | `TrackPreviewRenderer.renderWorldText` | 保留 XYZ / 半径 / 长度，另加坡度与累计总长 |
| `railMath.getHorizontalRadii()` | 反射读 `Rail.r1/r2` | MTR3 无 getter |
| `FLASHING` 状态 | `RenderHelper.flashingColor` | 语义一致：有效绿 / 无效红 |
| `PacketUpdateLastRailStyles` | 不使用 | LMEP 只预览，不修改轨道 |
| `placeNodeAndConnect` | ❌ 未移植 | 列入路线图 |

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 反射字段随 MTR 更新失效 | 全部封装在 `MtrRailAccess`，失败即降级为「不显示预览」，不崩溃 |
| 配置在加载前被读取 | 所有读取经访问器包装，异常时回退默认值 |
| 累计长度搜索在大型线网上爆炸 | 双重限界：深度上限 + 全局访问预算，且每秒最多重算一次 |
| 线网段长求和过慢 | 用 `approxLength3D`（2 次 `getPosition` + 勾股）代替逐段密集采样 |
| MTR4 被误装 | `mods.toml` 依赖范围 `[1.20.1-3.2.2-hotfix-2,1.20.1-4)` 明确排除 MTR4 |
| 服务端误加载客户端类 | `FMLEnvironment.dist` 守卫 + 客户端代码隔离在 `LmepClientSetup` |

## 6. 工程结构

```
src/main/java/com/luminiflux/lmep/
├── LmepMod.java               @Mod 入口（仅做 dist 守卫）
├── LmepClientSetup.java       客户端装配：配置 / 按键 / 事件注册
├── LmepConfig.java            ForgeConfigSpec（lmep-client.toml）
├── LmepKeybinds.java          K 预览开关，J HUD 开关
├── preview/
│   ├── PreviewState.java      单帧只读快照
│   ├── TrackPreviewManager.java  每帧计算（角度 / 轨道类型 / 有效性 / 统计 / 累计）
│   ├── TrackPreviewRenderer.java 世界渲染（幽灵轨道 / 标记 / 漂浮文字）
│   └── TrackPreviewHud.java      左下角屏幕面板（仅手持连接器时显示）
└── util/
    ├── MtrRailAccess.java     反射读 MTR 私有字段（缓存、可降级）
    ├── RailMathHelper.java    3D / 水平长度与低成本近似
    └── RenderHelper.java      轨道参数、闪烁色、丝带 / 线框绘制
```
